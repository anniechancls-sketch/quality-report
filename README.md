# 质量数据分析与报告生成工具

培训用轻量工具。把脱敏的现场巡检数据导入后，自动完成判定复算、双口径指标计算、周间差异拆解、AI 解读与报告导出（Word / Excel / PDF）。

核心原则：**数值全部由程序计算，AI 只负责文字归纳**，且 AI 输出的每个数字都要通过数字回查。

## 快速开始

环境要求：Node.js 18 或以上（无其他依赖，不需要联网安装任何包）。

```bash
cd 质量数据分析与报告生成工具
node src/app/server.js
```

启动后终端会打印访问地址，例如：

```
  本机访问：http://localhost:8787
  局域网访问：http://192.168.1.23:8787
```

浏览器打开即可使用。首次使用建议直接点「使用内置样例数据」，可在 1 分钟内走完整个流程。

## 目录说明

| 目录 | 内容 |
| --- | --- |
| `src/core/` | 业务逻辑：CSV/Excel 解析、列映射、判定、校验、指标、对比、备注归类 |
| `src/ai/` | 提示词装载、模型调用、数字回查、离线降级 |

| `src/app/` | 本地 HTTP 服务 |
| `public/` | 前端页面（原生 HTML/JS，无构建步骤） |
| `config/rules.json` | 限值、阈值、异常分类、模型参数 |
| `prompts/` | AI 提示词，改文案不需要改代码 |
| `data/samples/` | 7 周脱敏样例数据（452 条） |
| `output/` | 报告导出目录 |
| `docs/` | 需求文档、详细操作流程、完整交互逻辑、测试用例 |
| `tests/` | 自动化测试（Node 内置 test runner） |
| `prototype/` | 早期 HTML 原型，仅作对照，不参与运行 |

## 模型接入

默认调用 DeepSeek 的 OpenAI 兼容接口。Key 有三种提供方式，任选其一：

1. 启动前设置环境变量 `DEEPSEEK_API_KEY`
2. 在界面左侧「API Key」输入框临时填入（不落盘）
3. 界面选择「仅使用模板生成」或「模拟断网降级」，完全不调用模型

无论走哪条路径，报告都能正常生成：模型不可用时自动降级为模板文案。

## 部署方式

### 方式一　本机运行 + 局域网共享（推荐）

```bash
node src/app/server.js --host 0.0.0.0 --port 8787
```

同一局域网内的同事用终端打印的局域网地址即可访问，无需安装任何软件。适合培训现场与部门内部使用。

Windows 下可直接双击 `start.cmd`。

### 方式二　作为常驻服务

内网服务器或虚拟机上使用，配合进程守护工具（Windows 用 NSSM，Linux 用 systemd / pm2）注册为开机自启服务，对外提供固定地址。

### 方式三　容器化

```bash
docker build -t quality-report .
docker run -d -p 8787:8787 --name quality-report quality-report
```

详见 `Dockerfile`。注意：容器内默认没有浏览器，PDF 导出会自动降级为跳过该格式（Word 与 Excel 不受影响）；若需要容器内出 PDF，请使用 `Dockerfile` 注释中带 Chromium 的方案。

### 方式四　免费云平台（公网访问）

#### 4.1 Vercel（静态版，分享给同事最省事）

`site/` 目录是**纯静态版本**：判定、指标、差异分析、图表、Word/Excel 生成全部在使用者浏览器里完成，没有任何服务端请求。数据不上传、不需要数据库、不需要配置访问口令，部署完把网址发出去就行。

前置：把本项目推到一个 Git 仓库（GitHub / GitLab / Bitbucket 均可），Vercel 从仓库导入。

1. 打开 vercel.com，点 **Continue with GitHub**（或其他 Git 平台）登录。
2. 点 **Add New… → Project**，选中刚才的仓库，点 **Import**。
3. 在配置页填写：
   - **Framework Preset**：选 `Other`
   - **Root Directory**：保持仓库根目录不变（`vercel.json` 里已经写明 `"outputDirectory": "site"`）
   - **Build Command**：留空
   - **Output Directory**：留空（会被 `vercel.json` 覆盖为 `site`）
   - **Environment Variables**：不需要填任何变量
4. 点 **Deploy**，约 30 秒后拿到形如 `https://quality-report-xxxx.vercel.app` 的地址。
5. 把这个地址发给同事即可。

若不想用 `vercel.json`，也可以在第 3 步把 **Root Directory** 直接设为 `site`，效果相同。

命令行方式（需要联网安装 Vercel CLI）：

```bash
npx vercel --prod
```

静态版的已知差异，使用前需要知道：

1. **必须通过网址访问**：页面用的是浏览器原生 ES 模块，`file://` 双击打开会被浏览器拦截。本地预览请跑 `node tools/serve-static.js`，然后访问 `http://localhost:8080`。
2. **没有服务端就没有会话**：不存在"多人看到同一份结果"，每个人各自导入、各自导出，这恰好也是数据不落地的原因。
3. **AI 解读默认走模板**：需要模型润色时，由使用者在页面上自行填入 DeepSeek Key（只存在浏览器内存，刷新即失效）；不填也能生成完整报告。
4. **PDF 走浏览器打印**：点导出后会打开打印视图，用浏览器的"另存为 PDF"保存。Word 与 Excel 是直接下载文件。

#### 4.2 Render（完整版，带服务端）

仓库内已放好 `Dockerfile` 与 `render.yaml`，可一键部署到 Render 免费套餐（无需信用卡，自动分配 HTTPS 域名）。

操作步骤（约 5 分钟）：

1. 把本项目目录上传到你自己的 GitHub 仓库（私有仓库即可）。
2. 打开 render.com 注册账号（可用 GitHub 登录）。
3. 控制台选择 **New → Blueprint**，选中刚才的仓库，Render 会读取 `render.yaml` 自动创建服务。
4. 在服务的 **Environment** 里填写两个变量：
   - `ACCESS_PASSWORD`：**必须填**，访问口令。填了之后打开网址会弹出登录框，用户名随意填、口令填这个值。
   - `DEEPSEEK_API_KEY`：可选。不填则 AI 解读自动走模板生成，其余功能不受影响。
5. 等待构建完成，得到形如 `https://quality-report-xxxx.onrender.com` 的地址，把这个地址和口令发给同事即可。

**必须先知道的四点**

1. **免费套餐会自动休眠**：约 15 分钟无人访问后实例休眠，下次打开需要约 50 秒冷启动。培训现场请提前打开预热。
2. **数据落在境外**：Render 服务器在海外。如果只是用内置脱敏样例数据演示，没问题；**如果要导入真实质量数据，建议改用方式二的内网服务器**，这类数据出境的合规问题需要先跟信息安全部门确认。
3. **没有 ACCESS_PASSWORD 就等于完全公开**：任何人都能上传文件、看到所有人的分析结果与下载链接。公网部署时这个变量不是可选项。
4. **免费实例的文件系统是临时的**：实例重启后 `output/` 里的历史报告会丢失，会话也会失效，需要重新导入。培训演示不影响，长期归档请注意下载留存。

## 数据与安全

- 数据只在本机处理，不上传到任何第三方（AI 调用除外，仅发送程序算好的指标 JSON，不含原始明细）。
- API Key 不写入代码、配置文件、导出产物与日志。
- `output/` 为唯一落盘目录，可随时清空。
- 请勿把真实生产数据（未脱敏）导入或提交到仓库。

## 常见问题

**为什么合格率有两个数字？**
当期口径还原现场当时的判定；统一口径用同一套基准重算，用于跨周比较。两者必须同时展示，否则会把标准变化误读成质量变化。

**为什么 3周 和 5周 的对比结论是「无有效变化」？**
跨周比较使用统一口径序列，显著性也必须在统一口径上判定。统一口径下 3周 84.5%（约 73.1%–91.6%）、5周 96.3%（89.8%–98.7%），区间重叠。当期口径下 20.4pp 的差距在统一口径下收窄为 11.9pp，差额来自 3周有 5 条记录因标准变化而由不合格转为合格。

**为什么 7周 在图上带 * 号？**
7周只有 16 条记录，低于小样本阈值 30，样本量不足，相关结论仅供参考。

**备注里的报废米数为什么不加总？**
报废量单位统一为「米」，但备注中同时出现「公分」（描述追溯距离），两者是不同物理量，且多为估计值，直接相加会得出错误数字。工具一律按原文引用。
